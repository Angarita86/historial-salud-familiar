# Arquitectura técnica

La aplicación se organiza en tres capas que se comunican entre sí sin requerir servidores propios ni costos de infraestructura. El frontend es un sitio web estático construido con HTML, CSS y JavaScript, alojado directamente en GitHub Pages a partir de este mismo repositorio, y diseñado desde el inicio con una distribución mobile-first que prioriza el uso en celular sobre cualquier otra pantalla. Al abrirse, la aplicación solicita al usuario que inicie sesión con su cuenta de Google mediante el servicio de identidad de Google integrado en el propio navegador, de manera que la aplicación conoce de forma verificada el correo de quien está usándola sin necesidad de construir ni mantener un sistema propio de usuarios y contraseñas. Ese correo se usa además para resolver, del lado del backend, cuál es la ficha de miembro que le corresponde y así mostrarle por defecto únicamente su propia información; si desde el encabezado decide consultar la de otro integrante, el backend exige recibir junto con la solicitud el código de verificación de esa persona y lo contrasta contra el que tiene almacenado en la hoja de Miembros antes de entregar cualquier dato, de modo que la identidad de Google resuelve quién es cada usuario y el código de verificación resuelve, adicionalmente, a qué información ajena puede acceder.

La segunda capa es un proyecto de Google Apps Script vinculado al Google Sheets que funciona como base de datos. Este proyecto se despliega como una aplicación web propia de Google, con una dirección a la que el frontend envía todas sus solicitudes de lectura y escritura, y es también quien recibe los archivos adjuntos que el usuario sube desde el celular para almacenarlos en una carpeta de Google Drive organizada por integrante de la familia, dejando en la hoja de cálculo únicamente el enlace correspondiente. Sobre este mismo proyecto de Apps Script se configuran tareas programadas que se ejecutan de forma periódica en segundo plano, encargadas de revisar la proximidad de las citas y el estado de las tomas de medicamento pendientes para disparar, a través del servicio de correo de Google, los recordatorios dirigidos al miembro o a su cuidador según se haya definido en cada caso.

La tercera capa es la propia hoja de Google Sheets, que cumple el papel de base de datos relacional simplificada, con una pestaña por cada tipo de información tal como se describe en el documento de modelo de datos, y que puede consultarse o ajustarse manualmente en cualquier momento sin perder compatibilidad con la aplicación, dado que esta siempre lee y escribe siguiendo la misma estructura de columnas.

Esta arquitectura se eligió deliberadamente por no requerir experiencia previa en Google Cloud Console ni en el manejo de credenciales de servicio, ya que tanto Apps Script como el inicio de sesión de Google se configuran desde interfaces sencillas y dentro de los límites gratuitos de uso, adecuados sobradamente para un grupo familiar de hasta diez personas. El precio de esta simplicidad es que los recordatorios no llegan como notificaciones push instantáneas del celular sino como correos electrónicos, y que las tareas programadas de Apps Script se ejecutan en ciclos de algunos minutos y no de manera continua, razón por la cual el reintento de un recordatorio de medicamento no marcado como tomado ocurre en intervalos de quince a treinta minutos y no de forma inmediata.
